\chapter*{Executive Summary}
\addcontentsline{toc}{chapter}{Executive Summary}

MarketGyan is a Nepal-focused financial NLP research project extending the
existing Khabar AI data platform. Its revised contribution is
\textbf{NEPSE-Impact-500}: a human-adjudicated bilingual benchmark and
Qwen3-8B adapter for deciding whether Nepal-focused news is relevant to
NEPSE, classifying the event, mapping it to listed companies and sectors, and
producing an evidence-grounded potential-impact explanation. The novelty is
the Nepal-specific dataset, ontology, task definition, and evaluation design;
LoRA is an efficient adaptation method, not the research novelty.

Human review of the first schema exposed a material corpus-quality problem.
Several general-business stories passed schema validation and some were
approved with forced bullish, bearish, or neutral labels even though no
defensible NEPSE mechanism existed. The schema-v1 corpus is therefore frozen
as a pilot audit. As of \SnapshotTimestamp, it contains
\PilotApprovedCount{} approved, \PilotRejectedCount{} rejected,
\PendingCandidateCount{} pending, \QueuedCandidateCount{} queued, and
\FailedCandidateCount{} failed records.

Schema v2 and prompt \texttt{market-impact-v2} are implemented without
overwriting v1. The new contract separates relevance from potential impact,
uses a versioned Nepal-market ontology, grounds evidence by numbered source
sentence, stores independent reviewer annotations, and exports only
adjudicated gold records. The current NEPSE-Impact-500 gold corpus contains
\VTwoDirectSelectionCount{} direct records,
\VTwoIndirectSelectionCount{} indirect records, and
\VTwoNegativeSelectionCount{} hard negatives after targeted rebalance. It
passes the composition, language, source, symbol, and event-coverage gates.
The approved JSONL export and balanced duplicate-grouped split manifest are
ready for training reruns. The first model run has been audited, but compact
Qwen reruns have not yet produced replacement results. The model-error audit
flagged 40 high-priority records for source-grounded revalidation; those
records have now been submitted through the validation workflow, active audit
flags are cleared, and the gold export has been refreshed.

The modeling plan now compares Gemma before edits, base Qwen3-8B zero-shot,
base Qwen3-8B three-shot, XLM-R, English-only FinBERT, and MarketGyan
Qwen3-8B QLoRA \cite{finbert,fingpt,finllmSurvey,fintral,conneau2020xlmr,qwen3ModelCard,dettmers2023qlora}.
Static adaptation teaches the task, Nepal-market terminology, mappings, and
reasoning pattern. Current prices, policies, and announcements remain in
retrieval-augmented generation rather than model weights.

\textbf{Safety statement:} MarketGyan provides informational analysis based on
public data. It is not investment advice and does not place trades.

\chapter{Data Pipeline}

\section{End-to-end flow}

The implemented pipeline follows a controlled sequence:

\begin{enumerate}[leftmargin=1.8em]
  \item Collect public market data, financial news, and regulatory documents.
  \item Parse and normalize deterministic numeric fields without LLM inference.
  \item Store source links, publication and retrieval dates, field-level
        provenance, extraction status, and content hashes in MongoDB.
  \item Rank documents into direct-event, indirect, hard-negative, and reserve
        selection buckets without assigning gold labels.
  \item Queue selected documents with an idempotency key derived from content,
        model, prompt version, and schema version.
  \item Split the title and first 1,500 cleaned characters into numbered
        sentences and send only those sentences to Gemma.
  \item Validate the generated v2 candidate against the ontology, NEPSE
        registry, relevance-consistency rules, and sentence-ID evidence.
  \item Store valid candidates for review; keep each reviewer annotation
        separate from the generated proposal.
  \item Export only explicitly adjudicated schema-v2 gold records to JSONL.
  \item Validate the adjudication and composition gate, then freeze a
        balanced duplicate-grouped split manifest.
  \item Train and evaluate XLM-R, FinBERT, base Qwen, and Qwen3-8B QLoRA from
        the same frozen split.
  \item Index eligible documents and published reports in the dedicated
        MarketGyan Qdrant collection.
  \item Retrieve evidence, combine it with deterministic market data, and
        validate cited report or answer JSON before publication.
\end{enumerate}

Numeric market values, source metadata, dates, and retrieval metadata never
come from Gemma. This boundary prevents the structuring model from inventing
market prices or changing provenance.

\section{NEPSE market collection}

The current collector reads three public sources:

\begin{itemize}
  \item official NEPSE market pages for primary current-market fields
        \cite{nepseOfficial};
  \item ShareSansar for current values, listed securities, and historical index
        backfill \cite{shareSansar};
  \item MeroLagani as an additional current-market source and corroborator
        \cite{meroLagani}.
\end{itemize}

HTML and JSON responses are parsed using deterministic selectors and numeric
normalization. The system extracts index open, high, low, close, point and
percentage change, turnover, volume, transactions, and available
security-level values. A security registry normalizes listed symbols to
uppercase and records which sources observed each symbol.

Reconciliation is field-specific. Official NEPSE data has first priority.
ShareSansar supplies the first fallback, while MeroLagani corroborates current
values. If fallback values disagree beyond configured tolerances, the field is
withheld rather than averaged. Every stored snapshot contains provenance,
selected-source information, missing-field lists, warnings, and conflicts.

For a current daily snapshot to be marked complete, report-critical fields
must include index movement, turnover, sector rows, market breadth, and
available leader lists for gainers, losers, turnover, and volume. Historical
rows may remain partial when the source does not publish those fields; the
missing values remain explicit rather than inferred.

Historical backfill splits date ranges into provider-safe windows of at most
31 days. The current \SnapshotStartDate--\SnapshotEndDate{} backfill produced
\SnapshotCount{} partial snapshots. These are suitable for chronological
market context but are not represented as complete daily exchange records.

\section{Financial-news collection}

Financial news is collected from ShareSansar, OnlineKhabar Business, and
Kathmandu Post Money. ShareSansar collection follows category-specific cursor
pagination across NEPSE news, public issues, allotments, dividends, financial
analysis, listed shares, and stock-market coverage. URLs are deduplicated
across categories before full article paragraphs are retrieved.

OnlineKhabar collection traverses paginated Business RSS pages until the
requested start date is crossed, then retrieves full article paragraphs. If a
detail page is temporarily unavailable, the public RSS excerpt remains the
fallback. Kathmandu Post collection combines the Money landing page with
Money links from the general RSS feed and retrieves the full story paragraph
container. The site does not expose a working historical page parameter, so
Kathmandu Post remains supplementary rather than quota-critical.

All archive collectors enforce page and document limits, stop by publication
date, and reject article bodies shorter than 120 cleaned characters. This
keeps the six-month backfill bounded and prevents media-only stubs from
entering the structuring queue.

Each article is upserted by URL into the existing Khabar \texttt{Article}
collection with the \texttt{finance} topic and \texttt{business} category.
A separate \texttt{MarketDocument} references that article and records the
finance-specific title, language, source, publication date, retrieval date,
cleaned content, extraction method, content hash, and ingestion run. This
avoids duplicating complete article content while preserving a MarketGyan
contract.

\section{Regulatory-document collection}

The regulatory collector discovers public PDF links and metadata from NRB and
SEBON pages \cite{nrbOfficial,sebonOfficial}. SEBON notices expose direct PDF
links. NRB list entries frequently point to a landing URL that redirects to a
PDF; the collector records the landing page, follows the redirect, and can
also discover PDF attachments from an intermediate HTML page. It downloads
each resolved document, extracts machine-readable text, normalizes whitespace,
computes a content hash, and stores extraction status and errors.

The project intentionally excludes OCR and legacy-font conversion. Empty PDFs
and Nepali documents encoded with unsupported legacy fonts are marked failed.
The current snapshot contains \UsablePolicyDocumentCount{} usable and
\FailedPolicyDocumentCount{} failed policy documents. Failed extraction is
retained for audit and excluded from Gemma queueing, indexing, model training,
and report generation.

\section{Operational storage contracts}

\begin{description}[style=nextline]
  \item[\texttt{MarketSnapshot}] Daily index and turnover metrics, sectors,
  leaders, provenance, quality warnings, conflicts, and completion status.
  \item[\texttt{MarketDocument}] Article reference or original regulatory
  text, language, source metadata, cleaned text, content hash, extraction
  method, ingestion run, tags, companies, sectors, and reviewed sentiment.
  \item[\texttt{MarketSecurity}] Canonical active NEPSE symbol registry used
  to constrain symbol extraction.
  \item[\texttt{MarketLabel}] Idempotent structuring job, immutable input,
  generated candidate, versioned ontology metadata, numbered source sentences,
  selection bucket, model metadata, raw response, token usage, attempts,
  errors, revisions, and adjudication state.
  \item[\texttt{MarketAnnotation}] Independent annotation keyed by label and
  reviewer, with reviewer role, draft/submitted/rejected state, structured
  fields, rejection reason, and submission timestamp.
  \item[\texttt{MarketReaction}] Evaluation-only publication alignment,
  first- and third-session index/sector/symbol returns, abnormal returns,
  provenance, missing fields, and overlapping-event warnings.
  \item[\texttt{MarketIngestionRun}] Resumable run identity, requested date
  range, per-source counts, durations, warnings, and terminal status.
\end{description}

Ingestion uses upserts and stable source URLs, making repeated collection
idempotent. Source sections and regulatory landing-page provenance are
retained with the canonical document URL. Run states are \texttt{running}, \texttt{complete},
\texttt{partial}, or \texttt{failed}. Source-level failures do not erase
successful results from other collectors.

\chapter{API-Assisted Structuring}

\section{Gemma worker}

The structuring worker uses Google's hosted
\texttt{gemma-4-26b-a4b-it} endpoint \cite{googleGemma4}. Structuring is
disabled by default and requires an explicit environment flag and a
server-side API key. The client sends the key in the
\texttt{x-goog-api-key} header; the key is never exposed to client code or
stored in MongoDB.

The request pacer enforces at least four seconds between requests and defaults
to one concurrent worker. The current configured ceiling is 15 requests per
minute, but active project quotas must be confirmed in Google AI Studio
\cite{googleRateLimits}. HTTP 429 and server failures use \texttt{Retry-After}
when available, otherwise exponential backoff with jitter. Network requests
have a configurable timeout. The worker pauses after three consecutive
transient failures so a provider outage cannot drain the remaining queue.
Transient-only retry is capped at one additional job-level attempt; validation
failures are never automatically retried.

Schema-v1 queue states are:

\begin{center}
\texttt{queued -> processing -> pending\_review -> approved/rejected}
\end{center}

Schema v2 keeps the generated queue state separate from reviewer annotations
and uses explicit \texttt{adjudicated} or \texttt{excluded} gold status.

Failures transition to \texttt{failed} and can be retried. Jobs stuck in
\texttt{processing} for more than 15 minutes return to the queue. The
idempotency key combines the document content hash, Gemma model name, prompt
version, and schema version, preventing duplicate work under the same
configuration.

Queueing can be filtered by source and can use a deterministic source-balance
planner. The collection target prefers 220 ShareSansar, 150 OnlineKhabar, 30
Kathmandu Post, and 50 regulatory candidates. When one source lacks eligible
documents, the planner fills the deficit from ShareSansar and then
OnlineKhabar while capping any source at 60 percent of the 450-candidate
target. Failed and rejected jobs do not count toward the active target.

\section{Schema-v2 input boundary and function schema}

For prompt \texttt{market-impact-v2}, Gemma receives only:

\begin{itemize}
  \item the cleaned document title; and
  \item the first 1,500 relevant characters, truncated at a word boundary and
        represented as numbered source sentences.
\end{itemize}

The requested function output contains:

\begin{itemize}
  \item language and a short source-language factual summary;
  \item relevance: \texttt{direct}, \texttt{indirect}, or
        \texttt{not\_relevant};
  \item controlled event type, impact scope, direction, horizon, and
        mechanism;
  \item canonical sectors and registered NEPSE symbols;
  \item tags and low, medium, or high confidence;
  \item a cautious source-language rationale; and
  \item one or more exact numbered sentence IDs as evidence.
\end{itemize}

Allowed symbols are narrowed before the request using the symbol, company
name, and English or Nepali aliases stored in the security registry. Only
securities matched in the supplied title or excerpt enter the function
declaration. This supports bilingual company mentions without allowing Gemma
to choose an unrelated issuer from the full registry.

\section{Codex-assisted pre-review}

After first-pass Gemma generation, Codex can inspect each source and proposed
candidate in bounded batches. Corrections are validated with the same schema,
taxonomy, registered-symbol, and sentence-grounding checks as initial
generation. The system preserves the immutable Gemma candidate, stores the
Codex suggestion separately, records every changed field, and uses the valid
suggestion as the starting value in the human editor.

This pre-review is intended to remove obvious relevance, taxonomy,
overconfidence, and evidence-selection errors before the project reviewer
works through the queue. It never creates an independent annotation or gold
label and is not included in inter-annotator agreement measurement.

\section{Validation, independent annotation, and adjudication}

Generated output is normalized and rejected if:

\begin{itemize}
  \item a required string or array is missing;
  \item language, relevance, event, impact, or confidence is outside its enum;
  \item a submitted sector cannot be mapped to the canonical taxonomy;
  \item a symbol is not in the allowed-symbol set;
  \item a \texttt{not\_relevant} record contains an impact field, sector, or
        symbol that must be inapplicable;
  \item a relevant record lacks a defensible scope, event, mechanism, or
        sector/symbol mapping;
  \item summary or rationale is too short; or
  \item an evidence sentence ID is absent from the numbered source input.
\end{itemize}

The generated candidate remains immutable for acceptance and edit-rate
analysis. Each reviewer receives a separate \texttt{MarketAnnotation} record
and first decides relevance. Relevant records then expose event, scope,
direction, horizon, mechanism, sector, symbol, rationale, and evidence fields.
An adjudicator examines the independent annotations and explicitly creates
the gold value or excludes the record. Regeneration is blocked after an
annotation is submitted or a label is adjudicated.

Pending, excluded, v1, and non-adjudicated records cannot enter the v2
training export. At present, \VTwoAdjudicatedCount{} schema-v2 records are
adjudicated, exported, validated, and split. Non-gold records remain blocked
from export.

\section{Model-error revalidation workflow}

After the first model run, prediction artifacts were joined back to
\texttt{nepse-impact-500.jsonl} by label ID. The resulting audit ranks
examples where model disagreement suggests either a difficult case or a
possible annotation issue. The imported audit flagged 40 records, mostly
hard-negative general-business stories that XLM-R or Qwen predicted as
market-relevant, plus a smaller set of direct bullish records that baseline
models predicted as not relevant or uncertain. As of this snapshot, those
records have been reviewed and submitted, leaving
\RevalidationAuditCount{} active audit flags.

The audit is not a replacement for human judgment. It writes a
\texttt{revalidationAudit} marker to the corresponding \texttt{MarketLabel}
record, including priority score, model names, and disagreement reasons.
Submitting, rejecting, excluding, or adjudicating a flagged record clears the
marker. The refreshed gold export now passes dataset validation and the
500-record training gate.
Reviewers then open the same validation workflow, filter
\texttt{needsReview}, inspect the original source sentences and URL, and
submit the corrected annotation or confirm the existing gold label. A draft
keeps the audit flag active. Submission, rejection, exclusion, or
adjudication clears the flag and records a revision, preserving the audit
trail while avoiding manual JSONL edits.

relevance consistency, sentence-ID grounding, source metadata, dates,

\section{Balanced and duplicate-safe split}

Records are grouped by \texttt{duplicateGroupId} and assigned to a primary
balanced benchmark split:

\begin{itemize}
  \item 70\% train;
  \item 15\% validation; and
  \item 15\% test.
\end{itemize}

Keeping exact and near-duplicate groups together prevents the same or
equivalent source
content from leaking across splits. The first chronological split was useful
as a robustness check, but it created a large language and hard-negative shift:
training was mostly English/direct while testing contained many Nepali
hard-negative stories. The primary benchmark therefore uses deterministic
balanced allocation across relevance, language, event type, and impact
direction. A chronological duplicate-grouped split remains a secondary
robustness check.

\section{NEPSE-Impact-500 readiness}

The final gold corpus must contain exactly 500 adjudicated records:
300 direct events, 100 indirect sector or macroeconomic events, and 100 hard
negative general-business records. It must include at least 200 Nepali and
200 English records, 150 symbol-level records, 20 records in each core event
category, and 60 bullish and 60 bearish relevant examples. No source may
contribute more than 60 percent. All gold records are used; the pipeline does
not create synthetic labels or downsample the majority class.

The current gold export passes this gate: it contains
\VTwoDirectSelectionCount{} direct, \VTwoIndirectSelectionCount{} indirect,
and \VTwoNegativeSelectionCount{} not-relevant records; 299 English,
200 Nepali, and 1 mixed-language record; \VTwoSymbolSelectionCount{}
symbol-level records; and no source above 60 percent. The targeted event gaps
are closed with 36 earnings, 20 credit/financing, 20 regulation,
20 monetary/liquidity, and 20 sector/industry records. The frozen balanced
split contains 350 training records, 75 validation records, and 75 test
records.

The split is intentionally duplicate-grouped and label-balanced, so model
comparisons use the same test IDs without allowing near-duplicate leakage.

A stratified \SecondReviewTarget{}-record subset still needs independent
second annotation. Agreement reporting includes Cohen's kappa for relevance,
event type, and direction; micro-F1 for sector and symbol selection; and
sentence-selection F1 for evidence. Relevance and direction kappa must reach
0.70. Lower agreement triggers guideline revision and reannotation of
disagreement-heavy categories.

The first completed run produced the current baseline reference rather than

\XLMRRelevanceAccuracy{} accuracy and \XLMRRelevanceMacroFOne{} macro-F1,

direction, so the balanced split and revalidated audit cases should be used
before final thesis metrics are claimed.

\section{English-only FinBERT baseline}

The XLM-R notebook also runs \texttt{ProsusAI/finbert} on English relevant
records \cite{finbert}. It evaluates bullish, bearish, and neutral direction;
uncertain examples are excluded because the published FinBERT sentiment head
uses three classes. This baseline directly tests the proposal's
financial-domain adaptation motivation while making its English-only
limitation explicit.

The first English-only FinBERT evaluation reached \FinBERTAccuracy{} accuracy
and \FinBERTMacroFOne{} macro-F1, with \FinBERTErrors{} error on 14 English
relevant test rows. The small support makes it useful as a motivation and
sanity-check baseline, not as a sufficient standalone benchmark.

\section{Qwen3-8B QLoRA experiment}

The structured-output experiment uses the Qwen3-8B model family
\cite{qwen3ModelCard} loaded through \texttt{unsloth/Qwen3-8B} for the
Unsloth QLoRA training workflow \cite{unslothQwen3}. Each adjudicated row
becomes a two-message chat example: the user supplies the document title and
numbered source sentences, and the assistant supplies a compact reviewed
structure as JSON. Thinking mode is disabled in the chat template so training
targets only the required answer.

QLoRA reduces memory requirements by loading the base model in four-bit NF4
and training LoRA adapters instead of all model weights
\cite{dettmers2023qlora}. The notebook now uses Unsloth
\texttt{FastLanguageModel}, Unsloth gradient checkpointing, TRL
\texttt{SFTTrainer}, and response-only masking so the adapter learns only the
reviewed JSON response. The implemented configuration is:

    Warmup ratio & 0.05 \\

The Qwen target is intentionally compact. It contains only relevance, event
type, impact scope, impact direction, horizon, mechanism, sectors, symbols,
confidence, and evidence sentence IDs. It does not ask the adapter to generate
full evidence text, summaries, rationales, tags, or report prose. Those fields
are reconstructed later from RAG evidence and deterministic market data. This
change follows the first training-output audit, where full-gold JSON targets
caused truncation, low structured validity, and an all-direct relevance bias.
The rerun also oversamples indirect and hard-negative examples, including
Nepali hard negatives.

The minimum planned environment is an NVIDIA T4 with 16 GB VRAM in Kaggle or
Google Colab. Actual fit, throughput, and maximum sequence length must be
confirmed during reruns. The compact-Qwen configuration is code-complete, but
its results have not yet replaced the first low-validity Qwen output.
The \texttt{notebooks/qwen3\_8b\_qlora.ipynb} workflow evaluates base
Qwen3-8B zero-shot and three-shot before training the Unsloth QLoRA adapter on
the same frozen split as XLM-R. It generates deterministic JSON and exports
relevance, event, direction, sector, symbol, sentence-evidence, validity,
grounding, and confusion-matrix results.
Adapters, tokenizer files, predictions, plots, and metrics are archived for
download.

The first Qwen QLoRA run is therefore treated as a failure-analysis artifact.
It reached only \QwenFirstRunAccuracy{} relevance accuracy,
\QwenFirstRunMacroFOne{} relevance macro-F1, and
\QwenStructuredValidity{} structured-output validity. Of 75 test outputs,
\QwenInvalidJsonCount{} were invalid or truncated JSON and only
\QwenValidJsonCount{} were valid JSON. Among valid outputs, the model showed
an all-direct bias and produced \QwenHardNegativeFalsePositiveCount{}
hard-negative false positives. These findings justify the compact-label
target, balanced split, and hard-negative oversampling before rerunning Qwen.

\section{Evaluation plan}

The research report will combine dataset, model, retrieval, and end-to-end
measures:

\begin{itemize}
  \item Gemma acceptance without edits and field-level edit frequencies;
  \item annotation, exclusion, regeneration, and failure rates;
  \item structured-output validity;
  \item relevance, event-type, and direction macro-F1 and per-class metrics;
  \item per-language and per-event results;
  \item sector and symbol micro-F1;
  \item evidence sentence-selection F1 and grounding error rate;
  \item reviewer agreement by kappa and multilabel F1;
  \item balanced test coverage and chronological robustness coverage; and
  \item qualitative analysis of unsupported rationales and taxonomy errors;
  \item retrieval Precision@5 and citation correctness over at least 30
        manually judged finance queries; and
  \item report schema validity, freshness, generation latency, and
        end-to-end latency over at least 20 report or query scenarios.
\end{itemize}

Runtime inference remains disabled unless all of the following gates pass:

\begin{itemize}
  \item Qwen structured-output validity is at least 95\%;
  \item evidence grounding is at least 95\%;
  \item every relevance and direction class has usable measured performance;
        and
  \item QLoRA improves macro-F1 over base Qwen by at least 0.05 or the paired
        bootstrap 95\% confidence interval for improvement excludes zero.
\end{itemize}

\section{Ablations and market-reaction analysis}

Three ablations isolate the source of improvement: QLoRA versus base Qwen,
full training versus training without hard negatives, and RAG enabled versus
disabled for factual QA and grounded reporting. Every model condition uses
the same frozen test IDs.

Market reaction is evaluation-only. The baseline is the last trading close
before publication, followed by first- and third-trading-session returns.
NEPSE return is recorded for every relevant record; symbol or sector abnormal
return is computed only when deterministic history exists. Missing values and
overlapping same-symbol events remain explicit. Results report mean abnormal
return by predicted direction, material-movement sign agreement, and
bootstrap confidence intervals as exploratory association, never causation
or forecasting performance.

The repository includes 30 retrieval-query specifications and 20 system
scenario specifications. They define the benchmark but do not yet contain
measured judgments or results.

\section{Static adaptation versus dynamic knowledge}

Fine-tuning teaches stable behavior: Nepal-market terminology, institution and
company mappings, relevance judgment, event taxonomy, impact mechanisms,
structured output, and evidence selection. It is not treated as a reliable
store of changing prices, policies, announcements, or company facts. Those
facts remain in the provenance-aware MarketGyan Qdrant collection and are
retrieved at answer or report time. This separation permits a meaningful
adaptation experiment while reducing stale-knowledge and hallucination risk.

\section{Finance-specific retrieval}

The MarketGyan indexer uses a separate Qdrant collection and deterministic
overlapping chunks. Each payload stores chunk text, MongoDB document ID,
title, canonical URL, source, publication date, language, document type,
sectors, symbols, tags, and content hash. Reindexing is idempotent: unchanged
content keeps stable point identifiers, while changed content replaces stale
points. Search supports query, date, sector, source, language, and document
type filters.

\section{CrewAI, reports, and fail-closed operation}

The Python FastAPI service defines three sequential roles. The Researcher
calls the protected Node retrieval endpoint. The Analyst combines retrieved
chunks with deterministic market context. The Publisher produces strict JSON
with citations and the informational disclaimer. Citation URLs and excerpts
must match retrieved material before the response is accepted.

Node remains responsible for public APIs, report persistence, post-market
scheduling, and newsletter delivery. The scheduler runs ingestion, indexing,
generation, report archival, reindexing, and delivery in order. A failed or
uncited report prevents publication and suppresses the digest. Qdrant,
CrewAI, query inference, the scheduler, and digest delivery are all disabled
by default and fail closed when dependencies or credentials are unavailable.

\chapter{Risks and Limitations}

\section{Current limitations}

\begin{itemize}
  \item Historical market snapshots are partial and rely on one historical
        fallback source.
  \item Sector history, market leaders, complete breadth, and official
        corroboration are not available for every backfilled date.
  \item Legacy-font Nepali PDFs are not machine-readable and are permanently
        excluded by the project scope.
  \item The schema-v1 pool over-represents general business coverage and is
        not a valid NEPSE-impact benchmark.
  \item The v2 gold corpus passes the current composition gates and the
        model-error revalidation loop is submitted, but final claims still
        require rerunning every model on the refreshed balanced split.
  \item The first chronological split was source- and language-shifted because
        the collection timeline differs by outlet; it is retained only as a
        secondary robustness check.
  \item Gemma candidates may be fluent while assigning relevance, event, or
        mechanism incorrectly; schema validity alone is insufficient.
  \item Provider quotas, latency, and server errors remain operational risks
        for future regeneration and corpus expansion.
  \item Of the \VTwoFailedCount{} schema-v2 failed jobs,
        \TransientFailureCount{} are provider or network failures and
        \ValidationFailureCount{} are schema or grounding failures;
        \RetryableFailureCount{} transient jobs remain eligible under the
        current retry policy.
  \item Independent second-review agreement has not yet been measured.
  \item The first Qwen fine-tuning run failed structured-validity and bias
        gates; compact-label Qwen results do not exist yet.
  \item No live retrieval, agent, or inference benchmarks exist yet.
\end{itemize}

\section{Report update procedure}

For the next milestone, update the macros in
\texttt{status\_snapshot.tex}, append a dated entry to
\texttt{\textbackslash MarketGyanMilestoneHistory}, and add measured model
results only after the corresponding experiment artifacts exist. The stable
pipeline and model-design chapters should change only when implementation
behavior changes.

\chapter{Conclusion}

MarketGyan has progressed from a broad financial-news labeling pipeline to a
more defensible NEPSE-specific research design. The schema-v1 pilot exposed
the need for a relevance gate and hard negatives. Schema v2 now implements a
versioned ontology, bilingual aliases, sentence-grounded Gemma proposals,
independent annotations, explicit adjudication, duplicate-safe export,
reaction records, and model notebooks covering XLM-R, FinBERT, base Qwen, and
Qwen3-8B QLoRA. The methodology and quota-compliant 500-record adjudicated
dataset are implemented and exported. First XLM-R, FinBERT, and Qwen outputs
have been audited; Qwen failed validity and bias gates, and the
source-grounded revalidation queue is now cleared. Agreement results,
compact-Qwen rerun results, retrieval benchmarks, agent benchmarks, and
reaction analysis are not complete.
